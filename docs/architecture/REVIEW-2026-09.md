# Architecture Review — September 2026 (pre-development)

Scope: every file in the repo (README, TODO, ADRs, policies, Gradle, Kotlin, Wear,
backend, CI, agent config). The goal was to find gaps that would be expensive to fix once
Phase 0 code exists.

**Verdict:** The product thesis and phase/gate discipline are strong. The main risks were
not in the big picture. They were in platform constraints and data-contract details that
the docs had not pinned down yet: the Wear package identity, background mic limits,
crash-safe audio containers, capture-time timestamps, and deletion semantics. These are
now decided in ADR-0006…0010, or fixed in code.

## Findings and resolutions

| # | Severity | Finding | Resolution |
| --- | --- | --- | --- |
| 1 | Critical | Watch `applicationId` (`…aidailymemory.wear`) differed from the phone's. The Wear Data Layer only delivers between apps with the same package and signing key, so watch control could never have worked, and an applicationId can't be changed after release. | Fixed in `apps/wear/build.gradle.kts`; ADR-0008 |
| 2 | Critical | Mic foreground services started from the background are blocked (exception or silent audio). Watch "Start"/"Resume" and "resume after reboot" were planned without accounting for this. | ADR-0010: Pause keeps the service alive, honest `StartFailed`, no auto-start after reboot, silence detection; hardware spike moved to the start of Phase 0 |
| 3 | High | `.gitignore` used unanchored `audio/`, `exports/`, `transcripts/`, `logs/`: the natural source packages `…/aidailymemory/audio/` and `backend/app/exports/` would have been silently left out of commits. | Anchored to repo root; extension rules still block audio files everywhere |
| 4 | High | State machine: `reduce` **threw** on invalid events (a duplicate watch command could crash the recording service); no way out of `STARTING` on failure; no session identity or ordering for watch acks; no interruption reason; Pause could not override auto-recovery. | Reducer redesigned: `Applied/Ignored/Rejected`, `StartFailed`, `Stop` from `STARTING`, `sessionId` + monotonic `revision` + `CaptureProblem`, commands vs. signals. session-scoped signals. Exhaustive status × event matrix test (100% line, 98.8% branch) |
| 5 | High | Timezone/`local_date` were scheduled for Phase 4, but they can only be recorded correctly at capture time (Phase 0). | ADR-0006; moved to Phase 0 |
| 6 | High | MP4 via `MediaMuxer` (the default Android path) makes a crashed segment unplayable; `EncryptedFile` is deprecated; auth-bound Keystore keys fail while the phone is locked. | ADR-0007: append-safe container, Tink streaming AEAD, bounded loss = 1 segment |
| 7 | High | "Evidence is immutable" read as "never deletable", which conflicts with account deletion, retention, and GDPR erasure. The data model also had a single `source_transcript_id` and no corrections table. | ADR-0004 amendment; AGENTS.md rule 2 clarified; README data model revised |
| 8 | High | Supabase's auto-generated Data API would bypass the Memory Query Service. "Auth later" risked a schema without `user_id`. | ADR-0009 |
| 9 | Medium | Transcripts are third-party speech fed to LLMs and to users' agents over MCP, with no prompt-injection stance. | README "Untrusted Content"; Phase 2/5 TODO items |
| 10 | Medium | Unit economics: all-day recording × hosted ASR list prices can cost more than a typical subscription. Speech ratio was not being measured. | README "Unit economics"; Phase 0 measures speech ratio; Gate B requires a cost model |
| 11 | Medium | Consent law (all-party-consent jurisdictions) and provider data terms were first reviewed in Phase 8, after third-party voices reach providers in Phase 1. | Moved to Phase 1 prerequisites |
| 12 | Low | Backend: `pydantic-settings` was declared but unused; `/docs` + `/openapi.json` were public in every environment. | `app/config.py` + `create_app()`; docs are served only in development/test; tests added |
| 13 | Low | CI used a global Gradle instead of the wrapper, `uv sync` ignored the lockfile, tests weren't type-checked, and docs/skills still said "no wrapper yet". | CI and all docs/agent files normalized |

## Open decisions (need an owner, not code)

- **Quick Note model:** is it a marked window inside a running day session, or a short
  standalone session when idle? This affects the session schema (`kind`) and the watch UX.
- **Codec + segment length:** pick after the Phase 0 benchmark, among append-safe
  candidates only.
- **Billing path** (Play Billing vs. web): Phase 10 ADR. Play policy constrains linking
  out to web purchases.
- **On-device ASR:** keep it as an option if the Gate B cost model or privacy review
  favours it.

## Not changed (deliberately)

- No new infrastructure, modules, or later-phase code. Wear protocol, Room, Tink, and
  backend persistence are specified, not built.
- Semantic color tokens for recording state (Android design-system TODO) are still open.
  Note that the indicator currently uses dynamic `primary`, so the "recording" color
  changes with the user's wallpaper. Fixed recording tokens should be the first UI task.
